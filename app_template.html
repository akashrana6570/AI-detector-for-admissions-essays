How this works

The essay is split into sentences. Each sentence is run through a small trigram language model — trained only on a reference set of human-written admissions essays, sitting entirely in this page — to get an average per-word probability under "typical human phrasing." That number, plus nine other measurable properties of the text (how uniform the sentence lengths are, how often it uses stock transitional phrases, how often it uses contractions, lexical diversity, repeated three-word phrases, punctuation variety, and how repetitive the sentence openings are) form a feature vector. A logistic regression — ten weights and a bias, fit once on labeled example essays and frozen into this page — turns that vector into the essay-level probability shown above. No chat model is called at run time; every number on this page is arithmetic on the essay you pasted.

Signals used, and why

  • Stock-phrase rate — hits against a fixed list of phrases current LLMs over-use in this genre ("moreover," "it is a testament to," "this journey," "underscore," "delve," "boundless," etc.), per 100 words.
  • Contraction rate — human personal essays lean on contractions; heavily "polished" prose tends to drop them.
  • Sentence-length uniformity — the standard deviation of sentence length across the essay. Human writing is bursty: short sentences crash into long ones. Machine-smoothed prose tends toward an even rhythm.
  • Reference-model surprisal — average log-probability of each sentence's words under the trigram model.
  • Lexical diversity, repeated trigrams, sentence-opener repetition, punctuation variety — secondary structural signals.

Where the model draws the line

The model never asks a language model "is this AI?" and relays the answer. The only place a language-model-like component appears is the small trigram model used to get a token-probability number — an instrument, not a judge. The decision boundary (the ten weights below) is fit with ordinary logistic regression on the labeled feature vectors, entirely outside of any generative model.

Data — where it came from, and what it doesn't cover

This sandbox has no internet access, so nothing here was scraped from a real admissions-essay dataset or generated by calling an actual LLM API. Every training and test essay was written by hand for this project to imitate the two populations: a human set written to have the uneven rhythm, concrete detail, and informality of real personal statements, and an AI set written in the stock-phrase, triadic-list, evenly-paced register that current models reliably fall into on this exact task when asked for a "polished admissions essay." That is a real limitation, not a rounding error — a model tuned on one author's impression of "how AI writes admissions essays" will not generalize the way a model trained on thousands of real submissions from many schools and many AI systems would.

Coverage gaps worth naming directly: every essay is in the 150–260 word range (real submissions run longer and shorter); every AI example came from the same "voice" (one writer's model of GPT-style output, not five different real generators); there is no essay describing a STEM research project or a visual-arts portfolio; and the whole corpus is American college-admissions register — it says nothing about, say, UK personal statements or grad-school statements of purpose.

Three cases the detector gets confidently wrong

The ESL failure mode

Detectors like this one have a well-documented habit of flagging text by writers who learned English as a second language — because "simpler, more repetitive sentence structure" and "machine-generated" can look similar to a statistical model. We built this in as a check, not an afterthought: three short essays written in a fluent-but-non-native register (simpler verb forms, repeated sentence openers, fewer contractions) were scored the same way as everything else.

Result: this detector has exactly that problem. All three ESL-register essays score as more "AI-like" than the median genuinely human essay in the test set — not because they are machine-written, but because two of the strongest features in the model (contraction rate and lexical/structural repetition) correlate with non-native fluency for reasons that have nothing to do with authorship. We are reporting this as a known, unresolved limitation rather than hiding it: as built, this tool is not safe to use as the sole basis for an accusation against a non-native English writer, and any real deployment would need either a separate calibration for that population or a much larger, more representative training set before that risk goes away.
